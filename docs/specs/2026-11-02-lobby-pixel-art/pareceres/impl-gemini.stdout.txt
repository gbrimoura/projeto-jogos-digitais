### DEFECTS & SOURCE EVIDENCE (P1 / P2)

#### [P1] Godot Engine Import Dependency with `preload()`
- **Source Evidence**: 
  - `scripts/world/lobby_visual.gd` lines 4–6:
    ```gdscript
    const BACKDROP_TEXTURE: Texture2D = preload("res://assets/environment/factory_v1/lobby_v1/export/lobby-backdrop-576x324.png")
    const LEFT_DOOR_TEXTURE: Texture2D = preload("res://assets/environment/factory_v1/lobby_v1/export/elevator-door-left-32x56.png")
    const RIGHT_DOOR_TEXTURE: Texture2D = preload("res://assets/environment/factory_v1/lobby_v1/export/elevator-door-right-32x56.png")
    ```
  - Prompt/Manifest contract: `"no engine import performed"` / `"no Godot/import/runtime validation run."`
- **Impact**: In Godot 4.x, `preload("res://...png")` resolves through Godot’s asset pipeline (`.godot/imported/` and corresponding `.png.import` files). Because the PNG files were written exclusively by the external Aseprite binary without a Godot headless import pass, launching the game or compiling `lobby_visual.gd` before Godot scans the project will trigger parser load errors on those missing import artifacts.

Because `_draw_world()` draws an opaque `INK` box over `Rect2(888, 384, 176, 40)`, this 1px/2px offset is fully covered in-game, but represents an authoring discrepancy between generator layer `E` and the logical plaque coordinates.
