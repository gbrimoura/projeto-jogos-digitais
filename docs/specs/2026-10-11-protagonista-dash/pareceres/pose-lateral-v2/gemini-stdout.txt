### CONCRETE FINDINGS (PRIORITIZED BY LINE)

#### 1. [CRITICAL] Fatal Aseprite API Type Error in `Image:drawImage`
- **Location:** `SOURCE preview`, line 26 and line 59
  - Line 26: `sheetImage:drawImage(cel.image, cel.position.x, cel.position.y)`
  - Line 59: `canvas:drawImage(image, x, 0)`
- **Issue:** In the Aseprite Lua API, `Image:drawImage(srcImage, position [, opacity, blendMode])` expects the second argument (`position`) to be a `Point` object (`Point(x, y)`). 
  - Passing integers `cel.position.x` (line 26) or `x` (line 59) causes a fatal Lua runtime error: `Point expected, got number`.
  - Furthermore, on line 59, passing `0` as the third argument routes to `opacity = 0`, causing the frame to be drawn with 0% opacity (completely invisible) even if coordinates were accepted.
- **Correction:**
  - Line 26: `sheetImage:drawImage(cel.image, cel.position)` (or `Point(cel.position.x, cel.position.y)`)
  - Line 59: `canvas:drawImage(image, Point(x, 0))`

#### 2. [HIGH] Inverted Idle Facing Relative to Dash Vector
- **Location:** `SOURCE preview`, lines 77–80
  - Line 77: `addFrame(leftFacingIdleImage, 8, HOLD_MS)`
  - Line 78: `for i = 1, #DASH_POSE do addFrame(dashImages[DASH_POSE[i]], RIGHT_X[i], DASH_STEP_MS) end`
  - Line 79: `addFrame(idleImage, 58, HOLD_MS)`
  - Line 80: `for i = 1, #DASH_POSE do addFrame(reverseDashImages[DASH_POSE[i]], LEFT_X[i], DASH_STEP_MS) end`
- **Issue:** 
  - At `x = 8`, right before the protagonist dashes **rightward** (`+X`) across `RIGHT_X` (15 → 58), the animation displays `leftFacingIdleImage` (facing away from the dash trajectory).
  - At `x = 58`, right before the protagonist dashes **leftward** (`-X`) across `LEFT_X` (51 → 8), the animation displays `idleImage` (facing away from the return trajectory).
- **Correction:** Swap the idle orientations so the protagonist faces the direction of travel:
  - Line 77: `addFrame(idleImage, 8, HOLD_MS)`
  - Line 79: `addFrame(leftFacingIdleImage, 58, HOLD_MS)`

#### 3. [MEDIUM] Potential Cel Conflict on Preview Frame 1
- **Location:** `SOURCE preview`, line 68
  - Line 68: `local cel = preview:newCel(layer, frameNumber)`
- **Issue:** When creating a sprite via `Sprite(CANVAS_W, CANVAS_H)`, if `preview.layers[1]` is automatically provisioned with a cel on frame 1 by the runtime environment, `preview:newCel(layer, 1)` will throw `a cel already exists in the given layer/frame`.
- **Correction:** Guard cel retrieval on frame 1:
  ```lua
  local cel = (frameNumber == 1 and layer:cel(1)) or preview:newCel(layer, frameNumber)
  ```

#### 4. [LOW] Canvas Padding Asymmetry in Preview
- **Location:** `SOURCE preview`, lines 75–76
  - `CANVAS_W = 136`, `FRAME_W = 64`, travel distance = 50 px (`8` to `58`).
- **Issue:** At `x = 8`, the left margin is 8 px (`8 - 0`). At `x = 58`, the right margin is 14 px (`136 - (58 + 64)`). To achieve symmetric margins of 11 px on both edges:
  - Travel should range between `x = 11` and `x = 61` (midpoint 36 instead of 33).
